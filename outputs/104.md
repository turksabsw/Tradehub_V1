## 3. Degismesi Gereken Mevcut DocType'lar — Dinamik Link Filtre Plani

### Filtre Pattern Aciklamalari

Her bir bagimlilik iliskisi icin kullanilacak pattern'lar:

| Pattern | Aciklama | Ornek |
|---------|----------|-------|
| **P1: Tenant izolasyonu** | `frm.set_query('field', () => ({ filters: { tenant: frm.doc.tenant } }))` | Seller Profile → Tenant |
| **P2: Kademeli (Cascade)** | Parent field degistiginde child field'i filtrele ve sifirla | City → District → Neighborhood |
| **P3: Durum filtresi** | `{ status: 'Active' }` veya `{ is_active: 1 }` | Country, City, Category |
| **P4: Child table cascade** | `frm.set_query('field', 'child_table', (doc, cdt, cdn) => { ... })` | Address Item icinde City → District |
| **P5: Ozel sorgu** | `query: 'module.doctype.method'` server-side filtre | Ozel is mantigi gerektiren durumlar |
| **P6: Kendini haric tut** | `{ name: ['!=', frm.doc.name] }` | Category.parent_category |

### 3.1 Lokasyon Hiyerarsisi: Country → City → District → Neighborhood

Bu en kritik kademeli filtre zinciridir. Kullanici bir City sectiginde yalnizca o sehirdeki ilceler gorunmeli, ilce secildiginde yalnizca o ilcedeki mahalleler gorunmelidir.

#### 3.1.1 District (Mevcut: Kismi)

**JS Dosyasi:** `tradehub_core/doctype/district/district.js`
**Mevcut Durum:** `city` icin sadece `{ is_active: 1 }` filtresi var.
**Degisiklik:** Yeterli — District sadece City'ye bagli, cascade zincirinde parent.

```
District → [city → (is_active: 1 filtresi, MEVCUT)]
```

#### 3.1.2 Neighborhood (Mevcut: Kismi)

**JS Dosyasi:** `tradehub_core/doctype/neighborhood/neighborhood.js`
**Mevcut Durum:** `district` icin sadece `{ is_active: 1 }` filtresi var.
**Degisiklik Gerekli:** District, city'ye gore filtrelenmeli. City degistiginde district sifirlanmali.

```
Neighborhood → [
  city → district (city = frm.doc.city, is_active: 1)  ← EKLENECEK
  city degistiginde → district = '' (cascade clear)     ← EKLENECEK
]
```

**Onerilen JS:**
```javascript
// neighborhood.js — setup icine eklenecek
frm.set_query("district", function() {
    let filters = { is_active: 1 };
    if (frm.doc.city) {
        filters['city'] = frm.doc.city;
    }
    return { filters: filters };
});

// city degistiginde district sifirla
frappe.ui.form.on('Neighborhood', {
    city: function(frm) {
        frm.set_value('district', '');
    }
});
```

**Cross-ref Task 115:** Neighborhood zaten `district.city` uzerinden fetch_from kullanarak city'yi otomatik doldurur, ancak bu read_only. Kullanicinin onceden city filtreleyip sonra district secmesi icin ek city field'i gerekebilir (veya mevcut `city` read_only: 0 yapilarak).

#### 3.1.3 Address Item (Child Table — Mevcut: Yok)

**JS Dosyasi:** `tradehub_core/doctype/buyer_profile/buyer_profile.js` (ve Address Item kullanan tum DocType'lar)
**Mevcut Durum:** Seller Profile'da addresses + locations tablolari icin TAM cascade mevcut.
**Diger DocType'lar icin EKLENECEK.**

```
Address Item (in Buyer Profile, Organization, vb.) → [
  city → district (city = row.city, is_active: 1)           ← P4
  district → neighborhood (district = row.district, is_active: 1) ← P4
  city degistiginde → district = '', neighborhood = ''       ← cascade clear
  district degistiginde → neighborhood = ''                  ← cascade clear
]
```

**Onerilen JS (child table 3-arg):**
```javascript
// buyer_profile.js (veya ilgili DocType.js) — setup icine
frm.set_query('city', 'addresses', function(doc, cdt, cdn) {
    return { filters: { is_active: 1 } };
});
frm.set_query('district', 'addresses', function(doc, cdt, cdn) {
    let row = locals[cdt][cdn];
    return { filters: { city: row.city || '', is_active: 1 } };
});
frm.set_query('neighborhood', 'addresses', function(doc, cdt, cdn) {
    let row = locals[cdt][cdn];
    return { filters: { district: row.district || '', is_active: 1 } };
});

// cascade clear
frappe.ui.form.on('Address Item', {
    city: function(frm, cdt, cdn) {
        frappe.model.set_value(cdt, cdn, 'district', '');
        frappe.model.set_value(cdt, cdn, 'neighborhood', '');
    },
    district: function(frm, cdt, cdn) {
        frappe.model.set_value(cdt, cdn, 'neighborhood', '');
    }
});
```

**Etkilenen DocType'lar (Address Item kullananlar):**
- Buyer Profile (addresses)
- Organization (ilgili child table varsa)

1. Oncelikle seller/buyer secilir
2. fetch_from ile tenant auto-populate olur
3. Sonra tenant-bagli diger set_query filtreleri tetiklenir
4. Bu, seller/buyer field degisiklik event'inde `frm.refresh_fields()` cagrilarak saglanir.
