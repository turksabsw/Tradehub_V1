=== KEY EXISTING PATTERNS DISCOVERED ===

1. read_only:1 + fetch_from — Standard pattern for denormalized display fields:
   - tenant_name, seller_name, buyer_name, city_name, district_name
   - ~120 instances across all apps
   - Always paired: field with fetch_from AND read_only:1

2. hidden:1 — Used on:
   - naming_series fields (always hidden:1 + reqd:1)
   - NSM tree fields: lft, rgt, old_parent (in Product Category)
   - Deprecated/legacy fields (e.g., Seller Profile banking fields, Listing JSON fields)
   - verification_token in Consent Record

3. set_only_once:1 — NOT USED ANYWHERE in any tradehub app!
   - This is a GAP — fields like order.buyer, rfq.buyer, listing.seller should be set_only_once
   - Missing protection on critical linking fields

4. permlevel:1 — Used in:
   - Organization: verification_status, credit_limit, is_approved_buyer, is_approved_seller
   - Tenant: subscription_tier, max_sellers, max_listings_per_seller, commission_rate
   - Seller Profile: verification_status, seller_score, is_restricted, is_top_seller, is_premium_seller
   - This is the Frappe mechanism for admin-only field write protection

5. Status fields lacking read_only:1:
   - Most DocType status fields have NO read_only flag despite being workflow-controlled
   - Currently status can be manually edited; should be locked for most DocTypes
   - Only protected by workflow validation in Python controllers

=== CROSS-CUTTING PATTERNS ===

1. NAMING_SERIES PATTERN: Always {hidden:1, reqd:1, fieldtype:"Select"}
   Found in: 30+ DocTypes

2. FETCH_FROM + READ_ONLY PATTERN: 120+ instances
   Most common chains:
   - buyer → buyer_name, buyer_company, buyer_email, buyer_phone, buyer_segment
   - seller → seller_name, seller_company, seller_email, seller_phone
   - sku_product → product_name, sku_code, seller, seller_name, tenant, tenant_name
   - tenant → tenant_name
   - district → district_name, city, city_name, region
   - order → order_number, order_date, status, total_amount, buyer, seller, tenant (all)

3. COMPUTED TOTALS PATTERN: Always {read_only:1, default:"0"}
   Found on: subtotal, discount_amount, tax_amount, total_amount, grand_total,
   commission_amount, seller_payout, paid_amount, balance_amount, total_cost

4. TIMESTAMP PATTERN: Always {read_only:1, fieldtype:"Datetime"}
   Found on: created_at, modified_at, verified_at, approved_at, submitted_at,
   rejected_at, cancelled_at, shipped_at, delivered_at, completed_at, etc.

5. TENANT ISOLATION PATTERN:
   - With fetch_from: {fetch_from:"X.tenant", read_only:1} — SYSTEM
   - Without fetch_from: {fieldtype:"Link", options:"Tenant"} — ADMIN
   - tenant_name always: {fetch_from:"tenant.tenant_name", read_only:1} — SYSTEM

6. PERMLEVEL:1 PATTERN (Admin-only write protection):
   Used in: Organization, Tenant, Seller Profile
   Fields: verification_status, credit_limit, is_approved_*, subscription_tier,
           max_sellers, commission_rate, seller_score, is_restricted, is_top_seller

7. STATUS FIELD GAP:
   Most status fields (Select) have NO read_only:1 flag
   They are workflow-controlled but can currently be manually edited
   RECOMMENDATION: Add read_only:1 + permlevel:1 to all status fields

8. SET_ONLY_ONCE GAP:
   NOT USED ANYWHERE in any tradehub app
   Should be added to: buyer (on Order), seller (on Quotation, Listing),
   user (on Seller Profile, Buyer Profile), sku_product (on Sample Request)
