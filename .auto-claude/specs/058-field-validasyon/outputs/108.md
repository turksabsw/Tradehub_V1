# 108 — Child Table Calculation Functions Plan

## 1. Executive Summary

This document defines the complete child table calculation strategy for the TradeHub B2B Marketplace platform. It covers **22 child tables** across **8 Frappe apps** that contain numeric fields requiring row-level and/or parent-level calculations.

The canonical pattern is established by **Order → Order Item** (`order.js` + `order.py`), which implements a **dual-layer calculation architecture**:

- **Client-side (JS):** `frappe.ui.form.on()` event handlers on child table fields (`quantity`, `unit_price`, etc.) trigger immediate row recalculation and parent total aggregation for real-time UX feedback.
- **Server-side (Python):** `validate()` hook calls `calculate_totals()` to mirror the same formulas using `flt()`, ensuring data integrity regardless of client-side bypass.

Every child table with computed numeric fields must follow this dual-layer pattern. The server-side is the **single source of truth**; the client-side is for **UX responsiveness only**.

### Key Principles

1. **`flt()` everywhere** — All numeric operations use Frappe's `flt(value, precision)` to safely handle `None`, empty strings, and rounding.
2. **Mirror formulas** — JS and Python implement identical formulas; divergence is a bug.
3. **Bottom-up aggregation** — Row-level fields are calculated first, then parent fields aggregate from rows.
4. **Idempotent recalculation** — Calling `calculate_totals()` multiple times produces the same result.
5. **Row lifecycle awareness** — `items_add`, `items_remove`, and field-change events all trigger full parent recalculation.

## 3. Per-Child-Table Formula Documentation

### 3.1 Order Item (Canonical Pattern)

**Parent:** Order
**Child Table Field:** `items`
**Reference:** `order.js` + `order.py`

#### Row-Level Formulas

| Computed Field | Formula | Precision |
|---------------|---------|-----------|
| `amount` | `flt(quantity) * flt(unit_price)` | 2 |

#### Parent-Level Formulas

| Computed Field | Formula | Precision |
|---------------|---------|-----------|
| `subtotal` | `sum(items.amount)` | 2 |
| `discount_amount` | `flt(subtotal) * flt(discount_percentage) / 100` | 2 |
| `tax_amount` | `(flt(subtotal) - flt(discount_amount)) * flt(tax_rate) / 100` | 2 |
| `total_amount` | `flt(subtotal) - flt(discount_amount) + flt(tax_amount) + flt(shipping_cost)` | 2 |
| `advance_amount` | `flt(total_amount) * flt(advance_percentage) / 100` | 2 |
| `balance_amount` | `flt(total_amount) - flt(paid_amount)` | 2 |

#### Trigger Fields (JS events)
- `Order Item.quantity` → recalc row `amount` → `calculate_totals(frm)`
- `Order Item.unit_price` → recalc row `amount` → `calculate_totals(frm)`
- `Order.discount_percentage` → `calculate_totals(frm)`
- `Order.tax_rate` → `calculate_totals(frm)`
- `Order.shipping_cost` → `calculate_totals(frm)`
- `Order.advance_percentage` → `calculate_payment_amounts(frm)`
- `Order.paid_amount` → `calculate_payment_amounts(frm)`
- `Order Item.items_add` → `calculate_totals(frm)`
- `Order Item.items_remove` → `calculate_totals(frm)`

**Child Table Field:** `items`
**Reference:** `sub_order_item.py` — existing `calculate_totals()` method

#### Row-Level Formulas

| Computed Field | Formula | Precision |
|---------------|---------|-----------|
| `line_subtotal` | `flt(unit_price) * flt(qty)` | 2 |
| `discount_amount` | If `discount_type == "Percentage"`: `flt(line_subtotal) * flt(discount_value) / 100`; If `"Fixed"`: `min(flt(discount_value), flt(line_subtotal))` | 2 |

| Computed Field | Formula | Precision |

| `subtotal` | `sum(items.line_subtotal - items.discount_amount)` | 2 |
| `tax_amount` | `sum(items.tax_amount)` | 2 |
| `discount_amount` | `sum(items.discount_amount)` | 2 |
| `shipping_amount` | `sum(items.shipping_amount)` or parent-level override | 2 |
| `commission_amount` | `sum(items.commission_amount)` | 2 |
| `grand_total` | `flt(subtotal) + flt(shipping_amount) + flt(tax_amount)` | 2 |
| `commission_rate` | `flt(commission_amount) / flt(subtotal) * 100` (if subtotal > 0) | 2 |
| `seller_payout` | `flt(grand_total) - flt(commission_amount)` | 2 |

### 3.5 Cart Line

**Parent:** Cart
**Child Table Field:** `items`
**Reference:** `cart_line.py` — existing `calculate_totals()`, `calculate_discount()`, `calculate_tax()` methods

#### Row-Level Formulas

| Computed Field | Formula | Precision |
|---------------|---------|-----------|
| `discount_amount` (per unit) | If Percentage: `flt(unit_price) * min(flt(discount_value), 100) / 100`; If Fixed: `min(flt(discount_value), flt(unit_price))`; Else: 0 | 2 |
| `discounted_price` | `max(0, flt(unit_price) - flt(discount_amount_per_unit))` | 2 |
| `discount_amount` (total) | `flt(discount_amount_per_unit) * flt(qty)` | 2 |
| `taxable_amount` | If `price_includes_tax`: `base_total / (1 + tax_rate/100)`; Else: `base_total` | 2 |
| `tax_amount` | If `price_includes_tax`: `base_total - taxable_amount`; Else: `base_total * flt(tax_rate) / 100` | 2 |
| `line_total` | If `price_includes_tax`: `base_total`; Else: `base_total + flt(tax_amount)` | 2 |

Where `base_total = flt(qty) * (flt(discounted_price) or flt(unit_price))` and default `tax_rate = 18.0` (Turkish VAT).

#### Parent-Level Formulas

| Computed Field | Formula | Precision |
|---------------|---------|-----------|
| `subtotal` | `sum(items.line_total)` | 2 |
| `tax_amount` | `sum(items.tax_amount)` | 2 |
| `discount_amount` | `flt(coupon_discount) + flt(promotion_discount)` | 2 |
| `total_savings` | `savings_from_compare_at + flt(discount_amount)` | 2 |
| `grand_total` | `flt(subtotal) - flt(discount_amount) + flt(shipping_amount) + (flt(tax_amount) if not price_includes_tax else 0)` | 2 |

Where `savings_from_compare_at = sum(max(0, (compare_at_price - unit_price) * qty))` per item.

#### Trigger Fields (JS events needed)
- `Cart Line.qty` → `item.calculate_totals()` → `calculate_totals(frm)`
- `Cart Line.unit_price` → `item.calculate_totals()` → `calculate_totals(frm)`
- `Cart Line.discount_value` → `item.calculate_totals()` → `calculate_totals(frm)`
- `Cart Line.discount_type` → `item.calculate_totals()` → `calculate_totals(frm)`
- `Cart Line.tax_rate` → `item.calculate_totals()` → `calculate_totals(frm)`
- `Cart.coupon_discount` → `calculate_totals(frm)`
- `Cart.promotion_discount` → `calculate_totals(frm)`
- `Cart.shipping_amount` → `calculate_totals(frm)`
- `Cart Line.items_add` → `calculate_totals(frm)`
- `Cart Line.items_remove` → `calculate_totals(frm)`

### 3.11 KPI Template Item

**Parent:** KPI Template
**Child Table Field:** `items`
**Reference:** `kpi_template_item.py` — existing `calculate_score(value)` method

#### Row-Level Formulas (Score Calculation)

| Scoring Method | Formula |
|---------------|---------|
| Binary | `max_score` if value meets target, else `0` |
| Linear | `max_score * (value - critical_threshold) / (target_value - critical_threshold)` |
| Step | `max_score * {1.0 if value >= target, 0.7 if >= warning, 0.3 if >= critical, 0}` |
| Logarithmic | `max_score * log(1 + value) / log(1 + target_value)` |
| Exponential | `max_score * (exp(value/target_value) - 1) / (exp(1) - 1)` |

Bonus: If value exceeds target and `bonus_multiplier > 0`: `score * (1 + bonus_multiplier)`

#### Trigger Fields (JS events needed)
- `KPI Template Item.weight` → recalc parent total weight allocation
- `KPI Template Item.target_value` → informational (affects runtime scoring)
- `KPI Template Item.max_score` → recalc parent maximum possible score

```javascript
function calculate_item_amounts(frm, cdt, cdn) {
    var row = locals[cdt][cdn];
    row.line_subtotal = flt(row.unit_price) * flt(row.qty);

    // Discount
    if (row.discount_type === 'Percentage') {
        row.discount_amount = flt(row.line_subtotal) * flt(row.discount_value) / 100;
    } else if (row.discount_type === 'Fixed') {
        row.discount_amount = Math.min(flt(row.discount_value), flt(row.line_subtotal));
    } else {
        row.discount_amount = 0;
    }

    var taxable = flt(row.line_subtotal) - flt(row.discount_amount);
    row.tax_amount = taxable * flt(row.tax_rate) / 100;
    row.line_total = taxable + flt(row.tax_amount);
    row.commission_amount = taxable * flt(row.commission_rate) / 100;

    frm.refresh_field('items');
    calculate_sub_order_totals(frm);
}

function calculate_sub_order_totals(frm) {
    var subtotal = 0, tax_amount = 0, discount_amount = 0;
    var shipping_amount = 0, commission_amount = 0;

    (frm.doc.items || []).forEach(function(item) {
        subtotal += flt(item.line_subtotal) - flt(item.discount_amount);
        tax_amount += flt(item.tax_amount);
        discount_amount += flt(item.discount_amount);
        shipping_amount += flt(item.shipping_amount);
        commission_amount += flt(item.commission_amount);
    });

    frm.set_value('subtotal', subtotal);
    frm.set_value('tax_amount', tax_amount);
    frm.set_value('discount_amount', discount_amount);
    frm.set_value('shipping_amount', shipping_amount || flt(frm.doc.shipping_amount));
    frm.set_value('commission_amount', commission_amount);
    frm.set_value('grand_total', flt(subtotal) + flt(shipping_amount) + flt(tax_amount));

    if (flt(subtotal) > 0) {
        frm.set_value('commission_rate', flt(commission_amount) / flt(subtotal) * 100);
    }
    frm.set_value('seller_payout', flt(frm.doc.grand_total) - flt(commission_amount));
}
```

## 5. Python Server-Side `validate()` Plan

### 5.1 General Pattern

Every parent DocType with calculation-bearing child tables must call its `calculate_totals()` in `validate()`:

```python
def validate(self):
    """Validate document data before saving."""
    # ... other validations ...
    self.calculate_totals()  # Always last or near-last

def calculate_totals(self):
    """Calculate all totals from child table items."""
    subtotal = 0

    for item in self.items:
        # Row-level calculation
        item.amount = flt(item.quantity, 2) * flt(item.unit_price, 2)
        subtotal += flt(item.amount, 2)

    self.subtotal = flt(subtotal, 2)

    # Parent-level calculations
    if flt(self.discount_percentage) > 0:
        self.discount_amount = flt(
            flt(self.subtotal) * flt(self.discount_percentage) / 100, 2
        )
    else:
        self.discount_amount = 0

    taxable = flt(self.subtotal) - flt(self.discount_amount)
    if flt(self.tax_rate) > 0:
        self.tax_amount = flt(taxable * flt(self.tax_rate) / 100, 2)

    self.total_amount = flt(
        flt(self.subtotal) - flt(self.discount_amount)
        + flt(self.tax_amount) + flt(self.shipping_cost), 2
    )
```

### 5.3 Key `flt()` Usage Rules

1. **Always use `flt()` for any numeric field access:**
   ```python
   # Correct
   item.amount = flt(item.quantity, 2) * flt(item.unit_price, 2)

   # Wrong — will crash on None
   item.amount = item.quantity * item.unit_price
   ```

2. **Specify precision for currency fields:**
   ```python
   self.total_amount = flt(subtotal - discount + tax + shipping, 2)
   ```

3. **Guard division operations:**
   ```python
   if flt(self.subtotal) > 0:
       self.commission_rate = flt(self.commission_amount) / flt(self.subtotal) * 100
   ```

4. **Handle None child tables:**
   ```python
   for item in (self.items or []):
       # Safe even if items is None
   ```

**Server-side (Python):**

### 6.3 Row Modify

When a field in an existing row changes:

**Client-side (JS):**
```javascript
frappe.ui.form.on('ChildDocType', {
    field_name: function(frm, cdt, cdn) {
        var row = locals[cdt][cdn];
        // 1. Recalculate row-level computed fields
        row.amount = flt(row.quantity) * flt(row.unit_price);
        // 2. Refresh the child table display
        frm.refresh_field('items');
        // 3. Recalculate parent totals
        calculate_totals(frm);
    }
});
```

**Server-side (Python):**
- `calculate_totals()` recalculates all row-level fields and then parent fields
- This is **idempotent** — running it multiple times produces the same result

### 6.4 Recalculation Strategy Summary

| Event | JS Action | Python Action |
|-------|-----------|---------------|
| Row added | `items_add` → `calculate_totals(frm)` | `validate()` → `calculate_totals()` (iterates all rows) |
| Row removed | `items_remove` → `calculate_totals(frm)` | `validate()` → `calculate_totals()` (iterates remaining rows) |
| Row field changed | `field_name` → recalc row → `calculate_totals(frm)` | `validate()` → `calculate_totals()` (recalcs all rows + parent) |
| Parent field changed | `field_name` → `calculate_totals(frm)` | `validate()` → `calculate_totals()` |
| Bulk import/API | N/A (no JS) | `validate()` → `calculate_totals()` enforces correct values |
| Form load/refresh | `refresh` (no recalc needed — values already correct) | N/A |

### 6.5 Edge Cases

| Edge Case | Handling |
|-----------|----------|
| Empty child table (0 rows) | `subtotal = 0`, `total = 0 + shipping` — no division errors |
| All rows have qty = 0 | Row amounts = 0, subtotal = 0, total = shipping only |
| Null/undefined numeric field | `flt()` converts to 0 — safe default |
| Negative quantity entered | Validation in `validate_qty()` rejects negative values |
| Discount > line_subtotal | `min()` caps fixed discount; percentage capped at 100% |
| Tax rate = 0 | `tax_amount = 0` — multiplication by zero is safe |
| Division by zero (commission_rate) | Guard: `if flt(subtotal) > 0` before division |
| Concurrent edits | Server-side `validate()` is authoritative — last save wins |
| Row reordering | All calculations are order-independent (sum-based aggregation) |
