# 128.md - JSON Fields to Child Table Migration Plan

## 1. Executive Summary

This document provides a comprehensive inventory of all **73 JSON-type fields** across the 7 active TradeHub Frappe apps, categorized into **25 MIGRATE** candidates (structured, repeated data suitable for child tables) and **48 KEEP** candidates (dynamic/polymorphic/external API responses that should remain as JSON).

### Scope
- **Apps scanned:** tradehub_commerce, tradehub_seller, tradehub_catalog, tradehub_core, tradehub_compliance, tradehub_logistics, tradehub_marketing
- **Field types included:** `fieldtype: "JSON"` (50 fields) and `fieldtype: "Code"` with `options: "JSON"` (23 fields)
- **Excluded:** Backup apps (tr_tradehub_pre_split_backup, tr_tradehub_backup_20260206_153625, tr_tradehub), Frappe core, Code fields with non-JSON options (CSS, HTML, Python, JavaScript)

### Distribution by App

| App | JSON Fields | Code+JSON Fields | Total | MIGRATE | KEEP |
|-----|-------------|-------------------|-------|---------|------|
| tradehub_commerce | 22 | 2 | 24 | 9 | 15 |
| tradehub_seller | 10 | 0 | 10 | 8 | 2 |
| tradehub_compliance | 8 | 1 | 9 | 6 | 3 |
| tradehub_catalog | 3 | 11 | 14 | 1 | 13 |
| tradehub_core | 6 | 7 | 13 | 0 | 13 |
| tradehub_logistics | 1 | 1 | 2 | 0 | 2 |
| tradehub_marketing | 0 | 0 | 0 | 0 | 0 |
| **TOTAL** | **50** | **22** | **72** | **24** | **48** |

> Note: 1 additional field (Product Variant variant_images in tradehub_catalog) brings the total to 73 with 25 MIGRATE / 48 KEEP.

### Key Findings
1. **4 fields are already DEPRECATED** with existing child tables (Listing attributes/images/bulk_pricing_tiers, Seller Profile badges) - these need cleanup, not new migration
2. **6 Commission Rule fields** are the highest-impact MIGRATE candidates - they store lists of sellers/categories/days that should be Link-based child tables for referential integrity
3. **All Code+JSON fields are KEEP** - they store configurations, templates, external API responses, or computed data
4. **No app uses `frappe.parse_json` or `frappe.as_json`** - all use Python's standard `json.loads()` and `json.dumps()` exclusively
5. **Common error handling pattern**: `try: json.loads(value) except json.JSONDecodeError` is used consistently

## 5. Migration Script Strategy

### 5.1 General Migration Pattern

Every MIGRATE field follows this patch pattern:

```python
# patches/v2_0/migrate_{doctype}_{field}_to_child_table.py
import frappe
import json

def execute():
    """Migrate {DocType}.{field} JSON data to {ChildDocType} child table."""

    # 1. Get all records with non-empty JSON field
    records = frappe.get_all(
        "{DocType}",
        filters={"{field}": ["is", "set"]},
        fields=["name", "{field}"],
        limit_page_length=0
    )

    total = len(records)
    frappe.log(f"Migrating {total} {DocType} records...")

    for i, record in enumerate(records):
        try:
            # 2. Parse JSON data
            data = json.loads(record["{field}"])
            if not isinstance(data, list):
                continue

            # 3. Check if child table already has data (idempotent)
            existing = frappe.get_all(
                "{ChildDocType}",
                filters={"parent": record.name},
                limit=1
            )
            if existing:
                continue  # Already migrated

            # 4. Create child table rows
            doc = frappe.get_doc("{DocType}", record.name)
            for idx, item in enumerate(data):
                doc.append("{child_table_fieldname}", {
                    # Map JSON keys to child table fields
                    "{field1}": item.get("{json_key1}"),
                    "{field2}": item.get("{json_key2}"),
                    "idx": idx + 1
                })

            # 5. Save without triggering events
            doc.flags.ignore_validate = True
            doc.flags.ignore_permissions = True
            doc.save()

            if (i + 1) % 100 == 0:
                frappe.db.commit()
                frappe.log(f"  Migrated {i + 1}/{total}")

        except (json.JSONDecodeError, Exception) as e:
            frappe.log_error(
                f"Migration error for {DocType} {record.name}: {str(e)}",
                "JSON Migration Error"
            )

    frappe.db.commit()
    frappe.log(f"Migration complete: {total} records processed")
```

## 7. Rollback Strategy

### 7.1 During Migration
- **Keep original JSON field**: Do NOT delete the JSON field during migration. Set `hidden: 1` and `read_only: 1` instead.
- **Idempotent patches**: All migration patches check for existing child table data before creating duplicates.
- **Error logging**: All migration errors are logged to `frappe.log_error()` for post-migration review.

### 7.2 Post-Migration Validation
```python
def validate_migration(doctype, json_field, child_doctype, child_fieldname):
    """Verify all JSON data was successfully migrated to child table."""
    records = frappe.get_all(
        doctype,
        filters={json_field: ["is", "set"]},
        fields=["name", json_field],
        limit_page_length=0
    )

    mismatches = []
    for record in records:
        json_data = json.loads(record[json_field] or "[]")
        child_count = frappe.db.count(child_doctype, {"parent": record.name})

        if len(json_data) != child_count:
            mismatches.append({
                "name": record.name,
                "json_count": len(json_data),
                "child_count": child_count
            })

    return mismatches
```

### 7.3 Rollback Patch (Emergency)
```python
def rollback_migration(doctype, child_doctype, child_fieldname, json_field):
    """Reverse migration: reconstruct JSON from child table data."""
    records = frappe.get_all(doctype, limit_page_length=0)

    for record in records:
        children = frappe.get_all(
            child_doctype,
            filters={"parent": record.name},
            fields=["*"],
            order_by="idx asc"
        )

        if children:
            json_data = [serialize_child(c) for c in children]
            frappe.db.set_value(doctype, record.name, json_field, json.dumps(json_data))

    frappe.db.commit()
```

## 9. Python JSON Usage Patterns Across Apps

### 9.1 Common Patterns Identified

**Pattern 1: Conditional type checking**
```python
data = json.loads(value) if isinstance(value, str) else value
```
Used in: reviews/api.py, shipping_rule.py

**Pattern 2: Default empty collection**
```python
items = json.loads(self.field_name or "[]")  # Default to empty array
config = json.loads(self.field_name or "{}")  # Default to empty object
```
Used universally across all apps.

**Pattern 3: Try/except with JSONDecodeError**
```python
try:
    data = json.loads(value)
except json.JSONDecodeError:
    frappe.throw(_("Invalid JSON format"))
```
Used in: seller_tag_rule.py, sales_channel.py, eca_rule_action.py, tracking_event.py

**Pattern 4: Append-to-array**
```python
history = json.loads(self.field_name or "[]")
history.append(new_entry)
self.field_name = json.dumps(history)
```
Used in: seller_balance.py, review.py, moderation.py, risk_score.py

**Pattern 5: Formatted JSON output**
```python
self.field_name = json.dumps(data, indent=2)  # Pretty-printed
self.field_name = json.dumps(data, default=str)  # Datetime serialization
```
Used in: seo_meta.py, risk_score.py, eca/dispatcher.py

### 9.2 Library Usage
- **json.loads()**: 85+ uses across all apps
- **json.dumps()**: 30+ uses across all apps
- **frappe.parse_json**: 0 uses (not used anywhere)
- **frappe.as_json**: 0 uses (not used anywhere)

All apps use Python's standard `json` module exclusively.
