# 124 -- Cascading Discount System Plan

## 1. Executive Summary

This document defines the design for a **3-tier cascading (sequential) discount system** for the TradeHub B2B Marketplace platform. The system replaces the current single-discount model with three independent discount layers that apply **multiplicatively** rather than additively:

```
final_price = base_price * (1 - discount_1/100) * (1 - discount_2/100) * (1 - discount_3/100)
```

### Why Cascading (Not Additive)?

In B2B commerce, discounts originate from different sources (e.g., volume tier, customer loyalty, promotional campaign). A cascading model correctly represents the business reality that each discount applies to the **already-reduced price**, not to the original base. This prevents scenarios where combined discounts exceed the intended reduction and ensures each discount tier's impact is transparent to both buyer and seller.

### Current State

The TradeHub codebase currently uses **single-tier discount** across most DocTypes:
- **Order / Quotation:** `discount_percentage` (Percent) + `discount_amount` (Currency, read_only) -- single flat percentage applied to subtotal
- **Cart Line / Sub Order Item / Marketplace Order Item:** `discount_type` (Select: Percentage/Fixed Amount) + `discount_value` (Float) + `discount_amount` (Currency, read_only) -- single type-based discount per line
- **Cart:** Separate fields for `coupon_discount`, `promotion_discount`, `total_savings` -- multiple discount sources aggregated into a single sum, not cascaded
- **Listing:** `compare_at_price` + `selling_price` + `wholesale_price` + `bulk_pricing_tiers` (JSON) -- price-level discounting, not percentage-based cascading

### Scope of Change

This plan affects **11 DocTypes** across **4 apps** (commerce, seller, catalog, marketing). Each affected DocType will gain three cascading discount fields with computed intermediate amounts, collapsible UI tiers, real-time JS calculation, and server-side Python validation. The canonical `order.js calculate_totals()` and `order.py calculate_totals()` dual-layer pattern is extended to support the cascading formula.

### Key Principles

1. **Cascading, not additive** -- Each discount applies to the price after the previous discount, not to the original base.
2. **Dual-layer calculation** -- JS for UX responsiveness, Python in `validate()` for data integrity. Server-side is the single source of truth.
3. **`flt()` everywhere** -- All numeric operations use Frappe's `flt(value, precision)`.
4. **Progressive disclosure** -- Only Discount 1 is visible by default; Discount 2 and 3 are shown via collapsible sections/toggle buttons.
5. **Backward compatibility** -- Existing `discount_percentage` field is repurposed as `discount_1`. Migration path provided for existing data.

### 2.2 Existing Python Calculation Methods

#### `order.py calculate_totals()` (Lines 236-265)
```python
def calculate_totals(self):
    subtotal = 0
    if self.items:
        for item in self.items:
            item.amount = flt(item.quantity, 2) * flt(item.unit_price, 2)
            subtotal += item.amount
    self.subtotal = subtotal
    if self.discount_percentage:
        self.discount_amount = flt(subtotal * flt(self.discount_percentage) / 100, 2)
    else:
        self.discount_amount = 0
    taxable_amount = subtotal - flt(self.discount_amount)
    if self.tax_rate:
        self.tax_amount = flt(taxable_amount * flt(self.tax_rate) / 100, 2)
    self.total_amount = flt(
        subtotal - flt(self.discount_amount) +
        flt(self.tax_amount) + flt(self.shipping_cost), 2
    )
```

#### `cart_line.py calculate_discount()` (Lines 104-125)
```python
def calculate_discount(self):
    if not self.discount_type or flt(self.discount_value) <= 0:
        self.discount_amount = 0
        self.discounted_price = flt(self.unit_price)
        return
    if self.discount_type == "Percentage":
        discount_percent = min(flt(self.discount_value), 100)
        self.discount_amount = flt(self.unit_price) * discount_percent / 100
    elif self.discount_type == "Fixed Amount":
        self.discount_amount = min(flt(self.discount_value), flt(self.unit_price))
    else:
        self.discount_amount = 0
    self.discounted_price = max(0, flt(self.unit_price) - flt(self.discount_amount))
    self.discount_amount = flt(self.discount_amount) * flt(self.qty)
```

## 3. Cascading Formula Definition

### 3.1 Core Formula

The cascading discount formula applies three independent discount percentages **sequentially**:

```
price_after_d1 = base_price * (1 - discount_1 / 100)
price_after_d2 = price_after_d1 * (1 - discount_2 / 100)
final_price    = price_after_d2 * (1 - discount_3 / 100)
```

Or equivalently:

```
final_price = base_price * (1 - discount_1/100) * (1 - discount_2/100) * (1 - discount_3/100)
```

Each intermediate amount is computed and stored:

```
discount_1_amount = base_price * discount_1 / 100
discount_2_amount = (base_price - discount_1_amount) * discount_2 / 100
discount_3_amount = (base_price - discount_1_amount - discount_2_amount) * discount_3 / 100
total_discount_amount = discount_1_amount + discount_2_amount + discount_3_amount
```

### 3.2 Worked Examples

## 4. Cascading vs. Additive Discounts: Comparison

### 4.1 Mathematical Proof

Given base_price `P` and three discount percentages `d1`, `d2`, `d3`:

**Additive model:**
```
final = P * (1 - (d1 + d2 + d3) / 100)
```

**Cascading model:**
```
final = P * (1 - d1/100) * (1 - d2/100) * (1 - d3/100)
```

**Expanding the cascading model:**
```
final = P * (1 - d1/100 - d2/100 - d3/100
            + d1*d2/10000 + d1*d3/10000 + d2*d3/10000
            - d1*d2*d3/1000000)
```

The cross-product terms (`d1*d2/10000`, etc.) are always positive when discounts are positive, making the cascading result **always greater than or equal to** the additive result:

```
cascading_price >= additive_price   (when 0 <= d1, d2, d3 <= 100)
```

This means the cascading model gives the **seller a higher final price** (less total discount) than additive.

### 4.2 Numerical Comparison

| Scenario | Base | d1 | d2 | d3 | Additive Final | Cascading Final | Difference |
|----------|------|----|----|----|--------------:|---------------:|----------:|
| Small discounts | 1,000 | 10% | 5% | 3% | 820.00 | 829.35 | +9.35 |
| Medium discounts | 1,000 | 20% | 15% | 10% | 550.00 | 612.00 | +62.00 |
| Large discounts | 1,000 | 30% | 25% | 20% | 250.00 | 420.00 | +170.00 |
| Two only (d3=0) | 1,000 | 20% | 10% | 0% | 700.00 | 720.00 | +20.00 |
| Equal discounts | 1,000 | 10% | 10% | 10% | 700.00 | 729.00 | +29.00 |

**Key insight:** The divergence grows significantly as individual discount percentages increase. With d1=30%, d2=25%, d3=20%, additive gives 75% off (leaving 250), while cascading gives 58% off (leaving 420) -- a **170 TL difference on a 1,000 TL order**.

### 4.3 Why Cascading is Correct for B2B

1. **Business reality:** Volume discounts, loyalty discounts, and campaign discounts are negotiated independently. A 10% loyalty discount on top of a 20% volume discount means "10% off the already-discounted price," not "add 10% more off the original."
2. **Additive overflow risk:** Three discounts of 40%, 35%, 30% = 105% additive (negative price!). Cascading: `1000 * 0.60 * 0.65 * 0.70 = 273.00` -- always positive.
3. **Transparency:** Each tier's amount is visible and auditable independently.
4. **Industry standard:** SAP, Oracle NetSuite, and other B2B ERP systems use cascading/sequential discounts.

```javascript
// Toggle function
function toggle_discount_tiers(frm) {
    var show = cint(frm.doc.show_discount_tiers);
    frm.toggle_display('discount_2', show);
    frm.toggle_display('discount_2_amount', show);
    frm.toggle_display('discount_3', show);
    frm.toggle_display('discount_3_amount', show);

    if (!show) {
        if (flt(frm.doc.discount_2) > 0 || flt(frm.doc.discount_3) > 0) {
            frm.set_value('discount_2', 0);
            frm.set_value('discount_3', 0);
            calculate_totals(frm);
        }
    }
}
```

## 7. JS Real-Time Calculation

### 7.1 Parent-Level Cascading Discount (Order / Quotation Pattern)

This extends the existing `calculate_totals()` function.

```javascript
/**
 * Calculate cascading discount amounts and order totals.
 * Replaces the existing single-discount calculate_totals().
 *
 * Formula:
 *   d1_amount = subtotal * discount_1 / 100
 *   d2_amount = (subtotal - d1_amount) * discount_2 / 100
 *   d3_amount = (subtotal - d1_amount - d2_amount) * discount_3 / 100
 *   total_discount = d1_amount + d2_amount + d3_amount
 *   taxable = subtotal - total_discount
 *   tax = taxable * tax_rate / 100
 *   total = subtotal - total_discount + tax + shipping
 */
function calculate_totals(frm) {
    // Step 1: Calculate subtotal from items
    var subtotal = 0;
    if (frm.doc.items) {
        frm.doc.items.forEach(function(item) {
            subtotal += flt(item.amount);
        });
    }
    frm.set_value('subtotal', subtotal);

    // Step 2: Cascading discount calculation
    var d1 = flt(frm.doc.discount_1);
    var d2 = flt(frm.doc.discount_2);
    var d3 = flt(frm.doc.discount_3);

    var d1_amount = flt(subtotal) * d1 / 100;
    frm.set_value('discount_1_amount', flt(d1_amount, 2));

    var after_d1 = flt(subtotal) - flt(d1_amount);
    var d2_amount = flt(after_d1) * d2 / 100;
    frm.set_value('discount_2_amount', flt(d2_amount, 2));

    var after_d2 = flt(after_d1) - flt(d2_amount);
    var d3_amount = flt(after_d2) * d3 / 100;
    frm.set_value('discount_3_amount', flt(d3_amount, 2));

    var total_discount = flt(d1_amount) + flt(d2_amount) + flt(d3_amount);
    frm.set_value('total_discount_amount', flt(total_discount, 2));

    // Effective discount percentage
    if (flt(subtotal) > 0) {
        frm.set_value('effective_discount_pct', flt(total_discount / subtotal * 100, 2));
    } else {
        frm.set_value('effective_discount_pct', 0);
    }

    // Step 3: Tax on discounted amount
    var taxable_amount = flt(subtotal) - flt(total_discount);
    var tax_amount = 0;
    if (frm.doc.tax_rate) {
        tax_amount = flt(taxable_amount) * flt(frm.doc.tax_rate) / 100;
    }
    frm.set_value('tax_amount', flt(tax_amount, 2));

    // Step 4: Grand total
    var total = flt(subtotal) - flt(total_discount) + flt(tax_amount) + flt(frm.doc.shipping_cost);
    frm.set_value('total_amount', flt(total, 2));

    // Step 5: Payment amounts
    calculate_payment_amounts(frm);
}
```

### 7.3 Line-Item Cascading Discount (Cart Line / Sub Order Item Pattern)

```javascript
/**
 * Calculate cascading discount for a single line item.
 * Used in Cart Line, Sub Order Item, Marketplace Order Item.
 *
 * Formula (per unit):
 *   price_after_d1 = unit_price * (1 - discount_1/100)
 *   price_after_d2 = price_after_d1 * (1 - discount_2/100)
 *   discounted_price = price_after_d2 * (1 - discount_3/100)
 *   total_line_discount = (unit_price - discounted_price) * qty
 */
function calculate_line_cascading_discount(frm, row, cdt, cdn) {
    var unit_price = flt(row.unit_price);
    var qty = flt(row.qty || row.quantity);

    var d1 = flt(row.discount_1);
    var d2 = flt(row.discount_2);
    var d3 = flt(row.discount_3);

    // Per-unit cascading calculation
    var after_d1 = unit_price * (1 - d1 / 100);
    var d1_amount_per_unit = unit_price - after_d1;

    var after_d2 = after_d1 * (1 - d2 / 100);
    var d2_amount_per_unit = after_d1 - after_d2;

    var after_d3 = after_d2 * (1 - d3 / 100);
    var d3_amount_per_unit = after_d2 - after_d3;

    // Set per-unit amounts (multiplied by qty for total)
    frappe.model.set_value(cdt, cdn, 'discount_1_amount', flt(d1_amount_per_unit * qty, 2));
    frappe.model.set_value(cdt, cdn, 'discount_2_amount', flt(d2_amount_per_unit * qty, 2));
    frappe.model.set_value(cdt, cdn, 'discount_3_amount', flt(d3_amount_per_unit * qty, 2));

    // Discounted unit price
    frappe.model.set_value(cdt, cdn, 'discounted_price', flt(after_d3, 2));

    // Total line discount
    var total_discount = flt(d1_amount_per_unit + d2_amount_per_unit + d3_amount_per_unit) * qty;
    frappe.model.set_value(cdt, cdn, 'total_line_discount', flt(total_discount, 2));

    // Update line total (discounted_price * qty)
    var line_subtotal = flt(after_d3) * qty;
    frappe.model.set_value(cdt, cdn, 'line_subtotal', flt(line_subtotal, 2));

    frm.refresh_field('items');
    calculate_totals(frm);
}
```

## 8. Python Server-Side Validation

### 8.1 Parent-Level Cascading Discount (Order / Quotation)

```python
def calculate_totals(self):
    """Calculate order totals with cascading 3-tier discount."""
    subtotal = 0

    # Calculate subtotal from items
    if self.items:
        for item in self.items:
            item.amount = flt(item.quantity, 2) * flt(item.unit_price, 2)
            subtotal += flt(item.amount, 2)

    self.subtotal = flt(subtotal, 2)

    # Validate discount percentages
    self.validate_discount_percentages()

    # Cascading discount calculation
    d1 = flt(self.discount_1)
    d2 = flt(self.discount_2)
    d3 = flt(self.discount_3)

    self.discount_1_amount = flt(flt(self.subtotal) * d1 / 100, 2)

    after_d1 = flt(self.subtotal) - flt(self.discount_1_amount)
    self.discount_2_amount = flt(flt(after_d1) * d2 / 100, 2)

    after_d2 = flt(after_d1) - flt(self.discount_2_amount)
    self.discount_3_amount = flt(flt(after_d2) * d3 / 100, 2)

    self.total_discount_amount = flt(
        flt(self.discount_1_amount) +
        flt(self.discount_2_amount) +
        flt(self.discount_3_amount), 2
    )

    # Effective discount percentage
    if flt(self.subtotal) > 0:
        self.effective_discount_pct = flt(
            flt(self.total_discount_amount) / flt(self.subtotal) * 100, 2
        )
    else:
        self.effective_discount_pct = 0

    # Tax on discounted amount
    taxable = flt(self.subtotal) - flt(self.total_discount_amount)
    if self.tax_rate:
        self.tax_amount = flt(flt(taxable) * flt(self.tax_rate) / 100, 2)
    else:
        self.tax_amount = 0

    # Grand total
    self.total_amount = flt(
        flt(self.subtotal) -
        flt(self.total_discount_amount) +
        flt(self.tax_amount) +
        flt(self.shipping_cost), 2
    )
```

### 8.2 Discount Validation Method

```python
def validate_discount_percentages(self):
    """Validate all three discount tier percentages."""
    for tier_num in [1, 2, 3]:
        field = f"discount_{tier_num}"
        value = flt(getattr(self, field, 0))

        # Reject negative discounts
        if value < 0:
            frappe.throw(
                _("Discount {0} cannot be negative. Got: {1}%").format(
                    tier_num, value
                )
            )

        # Reject discounts over 100%
        if value > 100:
            frappe.throw(
                _("Discount {0} cannot exceed 100%. Got: {1}%").format(
                    tier_num, value
                )
            )

        # Warn on 100% discount (results in zero price for that tier)
        if value == 100 and tier_num == 1:
            frappe.msgprint(
                _("Warning: Discount 1 is 100%. This will result in zero price "
                  "regardless of other discount tiers."),
                indicator="orange",
                alert=True
            )

    # Validate that D2/D3 are zero if show_discount_tiers is off
    if not cint(self.show_discount_tiers):
        if flt(self.discount_2) > 0 or flt(self.discount_3) > 0:
            # Silently reset rather than throw (data cleanup)
            self.discount_2 = 0
            self.discount_3 = 0
```

### 8.3 Line-Item Cascading Discount (Sub Order Item / Cart Line)

```python
def calculate_cascading_discount(self):
    """Calculate cascading 3-tier discount for a line item."""
    unit_price = flt(self.unit_price)
    qty = flt(self.qty or self.quantity or 0)

    d1 = min(max(flt(self.discount_1), 0), 100)
    d2 = min(max(flt(self.discount_2), 0), 100)
    d3 = min(max(flt(self.discount_3), 0), 100)

    # Per-unit cascading calculation
    after_d1 = flt(unit_price) * (1 - d1 / 100)
    after_d2 = flt(after_d1) * (1 - d2 / 100)
    after_d3 = flt(after_d2) * (1 - d3 / 100)

    self.discounted_price = flt(after_d3, 2)

    # Discount amounts (total for line = per_unit * qty)
    self.discount_1_amount = flt((unit_price - after_d1) * qty, 2)
    self.discount_2_amount = flt((after_d1 - after_d2) * qty, 2)
    self.discount_3_amount = flt((after_d2 - after_d3) * qty, 2)

    self.total_line_discount = flt(
        flt(self.discount_1_amount) +
        flt(self.discount_2_amount) +
        flt(self.discount_3_amount), 2
    )

    # Line subtotal after discount
    self.line_subtotal = flt(flt(self.discounted_price) * qty, 2)
```

### 8.4 Edge Case Handling

| Edge Case | Behavior | Implementation |
|-----------|----------|---------------|
| **d1 = 0%, d2 = 0%, d3 = 0%** | No discount applied, all amounts = 0 | `flt(x) * 0 / 100 = 0` -- handled naturally |
| **d1 = 100%** | Price after D1 = 0, D2 and D3 have no effect (multiplying 0) | Warn user; `after_d1 = 0`, `after_d2 = 0`, `after_d3 = 0` |
| **Any discount > 100%** | Rejected with `frappe.throw()` | `validate_discount_percentages()` |
| **Negative discount** | Rejected with `frappe.throw()` | `validate_discount_percentages()` |
| **Subtotal = 0** | All discount amounts = 0, effective % = 0 | Division guard: `if flt(self.subtotal) > 0` |
| **Non-numeric input** | `flt()` converts to 0 | Frappe's `flt(None) = 0`, `flt("") = 0` |
| **Very small discount (0.01%)** | Precision maintained at 2 decimal places | `flt(value, 2)` truncation |
| **Floating point rounding** | Amounts rounded to 2 decimals at each step | `flt(intermediate_result, 2)` at every assignment |
| **show_discount_tiers unchecked but D2/D3 > 0** | D2 and D3 silently reset to 0 on save | Python `validate()` cleanup |
| **Cart with coupon + cascading discounts** | Coupon discount applies AFTER cascading tiers | `total = subtotal - cascading_discount - coupon_discount + tax + shipping` |
| **Child table with 0 rows** | Subtotal = 0, all discounts = 0 | Empty iteration produces `subtotal = 0` |

### 10.5 Coupon Integration

Coupons apply as a **separate layer** after cascading discounts. The order of discount application:

```
1. Calculate subtotal from items
2. Apply cascading discounts (D1 → D2 → D3) to get discounted_subtotal
3. Apply coupon discount on discounted_subtotal
4. Apply promotion discount on result
5. Calculate tax on final discounted amount
6. Add shipping
7. Grand total
```

**Formula:**
```
discounted_subtotal = subtotal * (1 - d1/100) * (1 - d2/100) * (1 - d3/100)
coupon_applied = calculate_coupon_discount(discounted_subtotal)
final_before_tax = discounted_subtotal - coupon_applied - promotion_discount
tax = final_before_tax * tax_rate / 100
grand_total = final_before_tax + tax + shipping
```

## Appendix B: Discount Tier Naming Convention

| Tier | Fieldname | Typical Use Case in B2B |
|------|-----------|------------------------|
| Discount 1 | `discount_1` | **Base/Volume Discount** -- Applied based on order quantity or total value. The primary, most-used discount. |
| Discount 2 | `discount_2` | **Customer/Loyalty Discount** -- Applied based on buyer category, tier, or relationship history. |
| Discount 3 | `discount_3` | **Campaign/Promotional Discount** -- Applied for time-limited campaigns, seasonal offers, or one-time promotions. |

These labels are suggestive; the system does not enforce the semantic meaning of each tier. Any percentage can be entered in any tier.
