# 134.md - Auto-fill & Read-Only Fields Plan

## Executive Summary

This document maps all Link/Select field to dependent field relationships across 7 TradeHub apps (203 DocTypes, 715 Link fields, 309 existing `fetch_from` relationships). It identifies **missing auto-fill relationships** and plans `fetch_from` + JS change handler implementations.

**Scan Results:**
- **309** existing `fetch_from` fields (all correctly using `read_only: 1`)
- **715** total Link fields across all TradeHub DocTypes
- **~180** Link fields with NO `fetch_from` at all, pointing to TradeHub DocTypes
- **~60** Link fields with partial `fetch_from` (some fields fetched, key ones missing)

---

## 1. Existing fetch_from Inventory (309 Fields)

### 1.1 Pattern: Geographic Cascade (City -> District -> Neighborhood)

Already well-implemented in:
- **District**: `city -> City` fetches `city_name`, `region`
- **Neighborhood**: `district -> District` fetches `district_name`, `city`, `city_name`, `region`
- **Address Item**: `city -> City` fetches `city_name`; `district -> District` fetches `district_name`; `neighborhood -> Neighborhood` fetches `neighborhood_name`
- **Location Item**: Same pattern as Address Item
- **Phone Code**: `city -> City` fetches `city_name`, `region`

## 3. JS Change Handler Implementation Plan

### 3.1 Cascading Select Handlers (Must Add)

These require **JS `change` handlers** to filter dependent Link fields dynamically.

#### Geographic Cascade (Existing Pattern - Extend to Seller Profile)

```javascript
// Pattern from Address Item - extend to Seller Profile, Buyer Profile
frappe.ui.form.on('Seller Profile', {
    city(frm) {
        // Clear dependent fields when city changes
        frm.set_value('district', '');
        frm.set_value('district_name', '');
        frm.set_value('neighborhood', '');
        frm.set_value('neighborhood_name', '');

        // Filter district by selected city
        frm.set_query('district', function() {
            return {
                filters: { city: frm.doc.city }
            };
        });
    },
    district(frm) {
        // Clear neighborhood when district changes
        frm.set_value('neighborhood', '');
        frm.set_value('neighborhood_name', '');

        // Filter neighborhood by selected district
        frm.set_query('neighborhood', function() {
            return {
                filters: { district: frm.doc.district }
            };
        });
    }
});
```

**Applies to:** Seller Profile (new `district`, `neighborhood` fields need cascade), Buyer Profile (if address fields added)

#### Category -> Subcategory Cascade

```javascript
// Listing, SKU, Import Job - filter subcategory by parent category
frappe.ui.form.on('Listing', {
    category(frm) {
        frm.set_value('subcategory', '');
        frm.set_query('subcategory', function() {
            return {
                filters: { parent_category: frm.doc.category }
            };
        });
    }
});
```

**Applies to:** Listing (`category` -> `subcategory`), Product Category (`parent_product_category`)

#### Seller Tier Cascade (Next/Previous)

```javascript
// Seller Tier - filter next_tier/previous_tier by tier_level
frappe.ui.form.on('Seller Tier', {
    setup(frm) {
        frm.set_query('next_tier', function() {
            return {
                filters: { tier_level: ['>', frm.doc.tier_level || 0] }
            };
        });
        frm.set_query('previous_tier', function() {
            return {
                filters: { tier_level: ['<', frm.doc.tier_level || 0] }
            };
        });
    }
});
```

### 3.2 Tenant Isolation Filter (Universal)

All DocTypes with `tenant` Link field should filter records by active tenant. This is a **global pattern**:

```javascript
// Applied to ALL forms with tenant field
frappe.ui.form.on('*', {
    setup(frm) {
        if (frm.fields_dict.tenant) {
            const tenant_filtered_links = [
                'seller', 'buyer', 'category', 'listing', 'organization',
                'commission_plan', 'seller_tier', 'shipping_rule'
            ];
            tenant_filtered_links.forEach(field => {
                if (frm.fields_dict[field]) {
                    frm.set_query(field, function() {
                        return {
                            filters: { tenant: frm.doc.tenant }
                        };
                    });
                }
            });
        }
    }
});
```

### 3.3 Status-Aware Filtering

Link fields should filter out inactive/draft records:

```javascript
// Example: Seller Profile link should only show active sellers
frm.set_query('seller', function() {
    return {
        filters: {
            status: 'Active',
            tenant: frm.doc.tenant
        }
    };
});
```

**Applies to:** `seller` (Active status), `buyer` (Active), `listing` (Published/Active), `seller_tier` (Active), `category` (Active/is_active), `carrier` (Active)

## 6. Implementation Rules

### Rule 1: Always pair `fetch_from` with `read_only: 1`
```json
{
    "fieldname": "seller_name",
    "fieldtype": "Data",
    "label": "Seller Name",
    "fetch_from": "seller.seller_name",
    "read_only": 1,
    "description": "Auto-filled from Seller Profile"
}
```

### Rule 2: Use `fetch_if_empty: 1` for optional enrichment
When the field should only auto-fill if not already set (e.g., when creating from another document):
```json
{
    "fetch_from": "seller.contact_email",
    "fetch_if_empty": 1,
    "read_only": 0
}
```

### Rule 3: Always add description
```json
{"description": "Auto-filled from [Source DocType]"}
```

### Rule 4: Place fetched fields immediately after their Link field
```json
"field_order": [
    "seller",        // Link field
    "seller_name",   // fetch_from field
    "seller_company" // fetch_from field
]
```

### Rule 5: JS handlers must clear dependent fields on change
```javascript
frm.doc.seller && frm.set_value({
    seller_name: '',
    seller_company: '',
    seller_email: ''
});
```

### Rule 6: Server-side validation in `validate()`
```python
def validate(self):
    # Refresh denormalized fields from source
    if self.seller:
        seller_doc = frappe.get_cached_doc("Seller Profile", self.seller)
        self.seller_name = seller_doc.seller_name
```
